# Scene type: 3d

Read `_common.md` first.

## Default: three.js inside HyperFrames (no extra install)
- Template `templates/scenes/three.html`: `<script type="module">` imports `../assets/vendor/three.module.min.js` (three 0.170, vendored by prepare-project).
- Build the scene once, then draw only in `render(t)` and hand it to `S.drive(render)`. No `requestAnimationFrame`, no `THREE.Clock`, no physics stepping by wall time.
- `preserveDrawingBuffer: true`, pixel ratio 1, canvas sized to the composition. Colours from `window.BRAND.colors`.
- HTML text overlays in `.os-frame` above the canvas, animated with the usual helpers.
- Software WebGL (no GPU) works but is slower: keep geometry modest (< 200k triangles), no heavy post-processing.

## Remotion + React Three Fiber (only when needed)
Set `three.physics: true` (Rapier) or `three.postfx: true` (bloom, DOF…) in the storyboard → engine `remotion`.
1. `node "$S/scripts/new-remotion.mjs" D` → `D/remotion/` (pinned remotion 4.0.537, R3F 9, drei, rapier, postprocessing), `src/brand.generated.ts`, `src/scenes.generated.ts`, `src/scenes/<id>.tsx`.
2. Ask, then `npm install` in `D/remotion` (~300 MB, once per project).
3. Write `src/scenes/<id>.tsx`: everything from `useCurrentFrame()`; physics must be deterministic (fixed timestep, seek-safe: simulate from frame 0 to the current frame, or precompute positions).
4. Stills/render through the normal tools. Flags: `ONE_STUDIO_REMOTION_GL` (default `swangle` on Linux/Windows, `angle` on macOS), `ONE_STUDIO_CHROME` to reuse a Chrome binary.
5. Licence: Remotion is free for individuals and companies ≤ 3 people; otherwise use the HyperFrames path.
